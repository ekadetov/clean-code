# Functions (F1-F4)

A function is a unit of work with a name attached. These rules keep that unit
small enough to reason about and honest about what it does.

## F1: More than ~3 arguments means the function is doing too much

Past three parameters, the function is usually either doing more than one
thing or needs a data structure instead of a parameter list.

Bad:
```
function createUser(name, email, age, country, timezone, language, newsletter)
```

Good:
```
type UserData = { name, email, age, country, timezone, language, newsletter }
function createUser(data: UserData)
```

## F2: No output arguments — return values instead

Mutating a parameter as a side effect hides what the function actually does
from its call site. Return the new value; let the caller decide what to do
with it.

Bad:
```
function appendFooter(report)
  report.append("Generated by System")   // mutates the argument
```

Good:
```
function withFooter(report)
  return report + "Generated by System"
```

## F3: No flag arguments

A boolean parameter that changes behavior means the function does at least
two different things wearing one name. Split it.

Bad:
```
function render(isTest)
  if isTest: renderTestPage()
  else: renderProductionPage()
```

Good:
```
function renderTestPage()
function renderProductionPage()
```

## F4: Delete dead functions

If nothing calls it, delete it — don't comment it out, don't keep it "just in
case." Version control already remembers it; a live codebase shouldn't have
to.

## Quick reference

| Rule | Principle |
|---|---|
| F1 | Max ~3 arguments — beyond that, use a type |
| F2 | Return values; don't mutate arguments as output |
| F3 | No boolean flag parameters — split into two functions |
| F4 | Unused function → delete it, don't keep it around |
